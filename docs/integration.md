# Интеграционный контракт 1.0.0

## Изменения приемки MVP

Общий технический кандидат находится в shared-contracts/. Он использует существующие цифровые региональные ключи соседнего regional-модуля. Миграция 0003 переводит media.post_regions из 83 ISO-кодов по проверяемому region-mapping.csv, сохраняя старые строки core и существующие UUID публикаций/источников. Пакет пока не ратифицирован; историческое описание ISO ниже относится к состоянию до 0003. В API для Москвы теперь RU-77. Справочник содержит также агрегаты RU/FD-*; они не являются субъектами.

Экспорт через posts/search/digest теперь возвращает **только** allowed-публикации текущей privacy-версии с совпадающим input_hash. text — максимум 240 символов безопасной выдержки; title маскируется, external_id/text_hash/author/raw_metadata исключены из публичной схемы. Полные исходные тексты через API не экспортируются. Метаданные исходных источников сохраняют атрибуцию, URL очищается от query/fragment и потенциально идентифицирующих slugs. Для изолированного внутреннего доступа к исходной БД нужны отдельные полномочия оператора.

Исторические source_id соседнего regional-модуля используют другую процедуру UUIDv5. Их автоматическая замена запрещена. До отдельного согласованного source mapping существующие IDs сохраняются; общий identity.py является предложением для новых источников всех модулей.

Модуль владеет только `media`. Таблицы `core` создаются и наполняются в самостоятельном режиме; интеграция должна передать владение ими платформе. Связей с `regional` и `practices` нет.

## Идентификаторы

`source_id = UUIDv5(72c4db98-6752-5fe0-a56d-af600628f13b, "source:" + lower(type) + ":" + normalized_url)`.
Нормализация: lowercase scheme и IDNA hostname, исключение default port, пустой path становится `/`, исключение fragment и utm_*, yclid, fbclid; сортировка query pairs с сохранением остальных параметров. HTTP и HTTPS намеренно разные. Изменение URL реестра требует явной процедуры переноса; не меняйте его произвольно.

`post_id = UUIDv5(source_id, NFC(strip(external_id)))`. RSS GUID/Atom ID имеет приоритет; fallback — нормализованный URL. Текстовый хеш используется для определения изменений. Копии разных источников сохраняются как разные публикации, что нужно для анализа источников; их можно группировать по text_hash. Частота публикаций не равна числу независимых событий.

Поставщик общей платформы не предоставил `regions.csv`. В репозитории находится **предварительный самостоятельный** список 83 ISO 3166-2 кодов, а не заявленный полный платформенный справочник. `valid_from` означает начало действия этого снимка в приложении, не дату образования региона. Неизвестные коды и спорные/измененные территории не придумываются. Перед объединением обязательно заменить snapshot на согласованный версионированный файл и подготовить явное отображение идентификаторов. Эта зависимость препятствует заявлению о полной совместимости.

## Экспорт

`GET /api/v1/media/posts?since=<ISO8601>&until=<ISO8601>&offset=0&limit=100&sort=asc`. Период полуоткрытый. Передавайте UTC offset в датах. Получайте страницы до total; экспортируйте при остановленном сборе, чтобы offset не смещался. Ответ содержит региональные и тематические связи, confidence, review_status и версию метода. Используйте post_id как ключ upsert; события изменения/удаления в этой версии API не реализованы. Для инкрементального экспорта удалений нужна следующая версия контракта или полный snapshot. Не объединяйте по названию региона.

`contracts/openapi.json` и `contracts/post.schema.json` генерируются из API и Pydantic; `/docs` и `/openapi.json` доступны в запущенном API. Верхнеуровневые темы фиксированы. Векторы e5 имеют размер 384; запросы используют `query:`, документы `passage:`. Поиск ограничен model + version, поэтому пространства не смешиваются. В MVP точный поиск без ANN; индекс ANN должен быть частичным для каждой версии, после измерения объема.
