# Защита данных

Конвейер: RSS → очистка HTML → Natasha 1.6.0 PER + регулярные выражения (email, телефоны, паспорт, СНИЛС, именованные структурированные ID, распознаваемый домашний адрес) → правила детского/чувствительного контекста → safe_title/safe_text отдельно от оригинала → PrivacyCheck с версией, смещениями и риском → allowed/held.

Имя — именованная сущность, а не автоматическое доказательство нарушения. Для публичного представления имена все равно скрываются. Наличие детского контекста и идентификаторов/чувствительных сведений блокирует выдачу. При недоступной Natasha — held, а не разрешение по regex. В findings нет совпавших строк. Примеры в тестах синтетические, телефоны из нулей и зарезервированный домен example.invalid не являются контактами граждан.

Публичные API возвращают только прошедшие проверку текущей версии публикации с совпадающим хешем исходного текста. Выдается до 240 символов безопасного представления, ссылка на источник и метаданные; полного текста и исходных внешних идентификаторов нет. Полнотекстовый поиск использует safe_* поля, embeddings вычисляются по safe_*; старые embeddings при обновлении текста удаляются. Дайджест и агрегаты применяют тот же барьер. Полный архив не экспортируется. Технические ошибки хранят только имя класса исключения; uvicorn access log отключен, чтобы поисковые запросы не попадали в журнал.

Ручная очередь: GET /api/v1/media/privacy/reviews и POST /api/v1/media/privacy/{post_id}/review, Bearer ADMIN_TOKEN. Очередь показывает маскированную версию и категории риска. Аналитик проверяет первоисточник в собственной контролируемой среде и принимает решение; API не предоставляет оригиналы даже с токеном. Решение относится к текущему хешу; изменение текста аннулирует проверку. Классификационные исправления сохраняются отдельно.

Исходный текст хранится только в локальной PostgreSQL; доступ имеет оператор БД, не публичный API. Порты только loopback. Для рабочей среды нужны отдельные права БД, TLS/аутентификация на шлюзе, защита диска/backup и журнал доступа. Срок удаления публикаций — RETENTION_DAYS (по умолчанию 90); ML/privacy/reviews удаляются каскадно. Backup/WAL очищаются оператором отдельно. Не архивируйте Docker logs с недоверенными исходными текстами. Runtime-логи текстов не содержат; используйте logging driver с ротацией.

Снижение риска не равно полной анонимизации. Возможны пропуски редких форм имен/адресов, идентификация по контексту и ложные срабатывания. Малый синтетический тест не доказывает производственную надежность. Не подключайте закрытые источники, реальные данные ведомств и внешние AI API.
