# Мониторинг информационного поля

Самостоятельный модуль «Навигатора детства». FastAPI + PostgreSQL 16/pgvector + Streamlit + отдельный worker. Кандидат MVP v0.1.0 проходит техническую приемку: [docs/mvp-readiness.md](docs/mvp-readiness.md). Автоматизация: [.github/workflows/ci.yml](.github/workflows/ci.yml). Docker Desktop владельцу для приемки не требуется: контейнеры проверяются GitHub Actions.

Новая публичная выдача содержит только безопасные выдержки текущей privacy-проверки. Исходные тексты не доступны через API, поиск или дайджест. Проверка Natasha + regex снижает риск, но не гарантирует полного обнаружения ПД. [Защита данных](docs/privacy.md), [запуск и CI](docs/deployment.md), [аудит](docs/mvp-audit.md).

## Запуск

Нужны Docker Engine и Docker Compose v2. В PowerShell из каталога проекта:

```powershell
Copy-Item .env.example .env
# Откройте .env и задайте длинный случайный ADMIN_TOKEN и собственный POSTGRES_PASSWORD.
docker compose up --build -d
docker compose logs -f worker
```

Интерфейс: http://localhost:8501. API / Swagger: http://localhost:8000/docs. Порты привязаны к loopback. Миграция и seed запускаются до сервисов автоматически; сбор повторяется каждые 15 минут. Не применяйте compose down -v к рабочим данным: это удалит БД.

При изменении POSTGRES_PASSWORD в существующем volume пароль БД автоматически не меняется. Для подключения вне Docker задайте согласованный DATABASE_URL. Секреты в .env не коммитятся. Доступ аналитика к изменению меток защищен ADMIN_TOKEN; чтение рассчитано на доверенную локальную машину. Для сетевого размещения нужен reverse proxy с TLS и аутентификацией.

```powershell
python -m pip install -e .
python -m pytest -q
python -m scripts.check_sources
```

Для интеграционного теста нужен отдельный PostgreSQL с миграциями, задайте TEST_DATABASE_URL. Не указывайте production DB. Проверка источников учитывает robots и сохраняет диагностический отчет. Три ленты есть в seed; успешность доступа зависит от сети, robots и правил издателя. Не следует считать все три подключенными до успешных collection_runs.

## Работа аналитика

Откройте ленту, задайте фильтры. В карточке проверьте темы и регионы, укажите идентификатор из справочника и основание корректировки. Только подтвержденные темы допускаются в дайджест. Частота публикаций отражает работу источников, не частоту событий. География по умолчанию означает упоминание, а не доказанное место события.

Полнотекстовый поиск работает без ML. Для локального семантического поиска см. [docs/nlp.md](docs/nlp.md). Источник ошибок сбора виден на странице качества. Расширенные коннекторы веб-страниц и Telegram, а также бот пока не включены.

## Данные и безопасность

Сбор только RSS, без автоматического обхода статей по ссылкам. Контролируются robots.txt, размер ответа, timeout и redirect targets; локальные IP запрещены. DNS-проверка не обеспечивает защиту от DNS rebinding, поэтому для недоверенного реестра нужен egress firewall; UI не позволяет добавлять произвольные источники. Не добавляйте закрытые ресурсы и не обходите запреты. robots не заменяет разрешение издателя и его условия использования.

Автор и произвольные сырые RSS-поля намеренно не сохраняются. Описание/заголовок могут содержать случайные персональные данные: доступ локальный, автоматическое удаление публикаций через 90 дней, дочерние ML-результаты удаляются каскадно. Срок копий PostgreSQL и резервных копий регулируйте отдельно. Профили граждан не создаются. Тексты во внешние AI API не передаются.

Контракт и экспорт: [docs/integration.md](docs/integration.md). Платформенный справочник регионов не предоставлен; включенный ISO snapshot требует согласования перед интеграцией.
